# 正式旅行資料契約

這是建立或整理資料時的最小欄位指引，不強制把既有專案改成某種格式。用JSON、試算表或結構化文件皆可；避免多份互相衝突的正式來源。確認原件獨立保留，產生物記所依據版本。

| 區塊 | 關鍵欄位 |
| --- | --- |
| 旅行 | 穩定ID、目的、起訖、出發地／目的地、各地時區、版本、當地及UTC更新時間、主揪、階段 |
| 成員 | 代號、角色、必要需求、願望優先度、步行休息、語言／手機、分組意願、分享範圍、待確認欄位 |
| 決策 | 決策ID、選項／取捨、確認者、時間、來源、取代的舊決策 |
| 每日／路段 | 穩定ID、起訖／入口、當地起訖時間及時區、交通模式／方向／出口、步行量、休息、停留、集合、固定預約ID、地圖與查核依據、可刪性 |
| 預約 | 獨立ID、供應商／分店、人數與拆單、代表人、時間／時區、票種、訂單／收據／票券各自欄位、預約狀態、付款狀態、報到要求、取消條件、原件、來源時間 |
| 授權 | 當次操作、對象／受眾、日期項目人數、金額上限／幣別、條件、證據、已用與未用範圍；不存憑證秘密 |
| 費用 | 獨立ID、預約ID、原幣、已付／承諾未付／估算、付款人、參與者、分攤規則、實付／退款與狀態、換算依據、手續費與尾差、結清狀態 |
| 備案 | 觸發條件、最晚切換時間、決定者、可執行動作、集合與費用影響、適用成員、需網路能力 |
| 待辦 | ID、負責人、到期時間／時區、依賴、狀態、下一步、提醒是否實際建立及回執 |
| 發布物 | 受眾、穩定網址、QR目標、版本、更新時間、下載檔名／大小／雜湊、正式資料版本、離線內容、原件位置、哪些檔須重新保存、通知是否發送／確認 |
| 驗收 | 任務、版本、成員代號、裝置／實際開啟App／瀏覽器／網路、步驟、預期、實際結果、證據層級、通過／失敗／未測／受阻、協助者／下一步；逐人結果保留於團體授權範圍，不公開健康或聯絡資料 |

未知用明確的「未提供／待查／未確認」或null，不能用0、false或空白冒充已確認。來源有原始網址／文件位置、適用日期與查核時間，注意勿在共用輸出洩漏私有路徑與敏感查詢參數。

狀態寫入採小範圍更新，保留原件與修改紀錄。避免序號重排導致別人的已存連結失效。成本加總依費用ID去重；同一筆預約付款與其帳本費用不得重算。

跨時區移動用明確日期與當地時區，避免只寫「明天下午」；跨日與夏令時間不能只用固定小時差推算。行程頁以當地資訊服務旅客，工程紀錄可另存UTC。
