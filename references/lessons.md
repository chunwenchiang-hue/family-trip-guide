# 匿名旅行案例：可重用的經驗

來源是一趟家人朋友日本秋季旅行的歷史討論與製作驗收。已移除姓名、信箱、單號、網站、筆記ID與私人附件；以下是方法教訓，沒有重新查證任何景點今日狀態。

| 發生過的問題 | 下次如何處理 |
| --- | --- |
| 手機頁面精簡後漏掉預約與外語卡 | 先記現有功能基準，減字後做回歸；不要用「更簡單」默默改變功能 |
| 發音按鈕存在，手機語音清單卻空白 | 實際播放與使用者聽音驗證；準備音訊或文字備援 |
| 基礎系統男聲可播放，卻被使用者評為機械、不好聽 | 可用不等於好聽。優先自然台灣女聲，先用約20–30秒真實文稿確認音色與語速，再製作全部；失敗時不能偷偷退回基礎音色 |
| QR難找，多入口與舊檔讓主揪困惑 | 一個穩定同行入口，清楚受眾與版本，舊教學歸檔 |
| 確認信需主揪登入、同主旨信被合併 | 每筆預約獨立摘要與原件入口，保存供同行使用的必要憑證 |
| 接駁發車被含糊寫成到站；纜車與花園不同開放時間 | 分別核對，倒推真實可參觀時間，提早出門不能讓景點提早開門 |
| 地圖理論步行分鐘數太樂觀 | 加入團體步速、進站、電梯、行李與休息；不固定所有人都適用 |
| 訂不到熱門交通後沿用網友路線 | 核休館、車輛限制、入口、體力和固定晚餐，挑必要景點與刪除點 |
| 新增景點讓行程越排越滿 | 先討論取代休息或候補的成本，保留重要預約與成員負荷 |
| 證據只有收據號，沒有另列預約號 | 保持原來類型，不能把參考號冒稱有效入場憑證 |
| 自動翻譯把正確英文姓名顯示成錯中文 | 切回原文核對，避免因翻譯錯誤改掉正確資料 |
| 受眾決策後來變更，舊資料仍寫私人版 | 依最新明確決策處理，不把曾經的私密／公開選擇當永久設定 |
| 新網站更新了，舊行程PDF仍保留 | 明示版本落差與最新指示，必要備援同步；保留原件不等於默認內容仍最新 |
| 桌面390px測試被誤認為iPhone驗收 | 逐項記證據層級，不能代稱原生App、實體出聲或飛航模式通過 |
| 新版離線下載按鈕藏在長行程底部 | 首頁上方放下載入口，旁邊提供試播與預約快捷；原備忘錄直達同一區 |
| 不同版本的下載檔名相同，旅客誤開舊檔 | 頁面與檔名都有可辨認版本／日期，通知舊檔不會自動更新；下載後關掉再重開指定版本 |
| 下載成功，手機檔案預覽卻不能點按或出聲 | 預覽不是完整瀏覽器；先辨認開啟App與支援情況，給連網入口、原生文字及已存PDF備援 |
| 單檔HTML仍引用不存在的相鄰下載檔 | 分別檢查網站與已存單檔；內嵌必要資產，從單檔取得更新時回穩定線上入口，不指向不存在的本機相對檔案 |
| 無預約號的報到卡只寫「核對姓名」，現場仍要翻原件找姓名 | 由原件核對後把代表人、日期、時刻與人數寫入摘要及放大卡；保留正式憑證入口，不發明預約號 |
| 主揪一支手機正常，便把全團標為就緒 | 逐人測同步、相機／連結、下載重開、聲音、預約與飛航模式；不能操作者有協助者或紙本 |

此案例沒有完整保存最早選地理由與每人願望，不能假裝已復原。新旅行仍需短訪談；日本、長輩、五人、某款備忘錄或分兩台車均非通用強制條件。景點聲音已依使用者後續明確指示，優先採用自然台灣女聲；配方及試聽確認流程見 [自然女聲](guide-voice.md)，不是把本案例舊男聲延續為預設。
