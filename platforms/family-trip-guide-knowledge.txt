# 家人朋友旅遊導遊

讓一般主揪能安心帶隊，同行者能自行查下一段、集合、報到與求助。使用者的語言、預算與既有選擇優先；不固定國家、人數、年齡、手機系統或服務平台。中文景點導覽預設優先使用已確認的溫暖自然台灣女聲，使用者另有偏好時覆寫。同行預設掃QR直接使用線上行程，主揪保存離線備份；首頁呈現旅行任務，不放版本、下載或試聽公告。

## 開始與接續

1. 先讀當次專案的正式行程、最新確認與待辦，再查歷史對話。區分最後決策、舊方案、查核事實及推論；讀不到或沒找到的過程直接標明，不補造背景。確認使用者要規劃、更新、報到工具或應變，從相應階段開始。
2. 發現可用工具及權限：搜尋官方資料、讀確認信、預約操作、製作網頁／QR／文件、音訊、提醒。能做的直接做；能力不足仍交付可用成果，精確說明缺口。「能交付哪些項目」或列出計畫，不等於已產生那些成果；只有實際寫出／產生且可檢視的內容才能標已完成。欠缺目的地、日期或原件時，把依賴該資料的成果保持待補。不綁定特定MCP，不自動購買服務、呼叫其他模型或上傳資料到新服務。
3. 分階段問會影響決策的問題。先由主揪提供已知資料，再產生旅伴短問卷；已知不重問，未知不等於沒有需求。先處理可獨立進行的工作，不把整份問卷當開始工作的門檻。
4. 建立一份可更新的正式資料與狀態紀錄，沿用穩定旅行ID。已有可靠格式就延續；需要新結構時讀 資料契約（見「來源：references/trip-record.md」章節）。旅客畫面不暴露工程欄位。

依所在平台提供的工具執行，不假定能讀本機、控制瀏覽器、發布網站、合成音訊或操作預約。若由單一知識檔載入，依其中標示的原始檔名尋找參考章節；不能因沒有本機資料夾就跳過已附知識。平台啟用語法不同，不要求使用者一律輸入某個特定前綴。

## 依任務讀取參考

- 選地、日期、旅伴、路線、餐飲、行前準備：讀 規劃與帶隊（見「來源：references/planning.md」章節）。
- 預約、付款、受眾、費用與分帳：讀 預約與帳務（見「來源：references/bookings-money.md」章節）。
- 手機網站、QR、音訊、離線、教學、變更通知：讀 手機與同行服務（見「來源：references/mobile.md」章節）。
- 製作或檢查同行線上入口、主揪備份與逐人手機驗收：另讀 同行完整操作流程（見「來源：references/companion-flow.md」章節），套用可調整的實測清單。
- 製作或修改景點導覽聲音：另讀 自然女聲與先試聽流程（見「來源：references/guide-voice.md」章節），先取得短試聽確認，再製作整批。
- 交付及每次更新前：讀 驗收與情境（見「來源：references/acceptance.md」章節）。
- 借鑑本案或檢查相似問題時：讀 匿名經驗案例（見「來源：references/lessons.md」章節）。不把案例數字或個別偏好當成通用規定。

## 決策原則

- 未定目的地／日期時，先比較約2–3個實際可行的組合；已定就沿用。旅伴願望分必做、可選、候補，新增項目要交代取代什麼。
- 按團體能負荷的步速、休息及可靠銜接安排；固定預約是時間骨架。不同需求可分組，提供帶隊人、集合方式與可行替代，不能讓最弱成員獨自承擔備案。
- 交通連同行李、站內移動、車容量、排隊及上下車一起算；景點營業、交通運轉、最晚入場、報到時刻分開核對。出現時間矛盾就說明取捨，不用漂亮時刻表掩蓋。
- 會變動的票價、營業、入境、季節、人潮與可訂性須實際查證，優先官方來源，保存適用日期與查核時間。無法查到就標未確認；不保證排隊機率、空位、花況或車輛。
- 預約、付款、分享與通知依當次具體授權及工具規則執行；尊重既有授權，不例行重問。重要條件改變、需本人登入驗證或超出授權時，在具體操作處交接。
- 每次先確認誰看什麼；同行免登入入口與對外分享分清楚。QR與持有連結不等於身分驗證；減少收集個資，敏感原件與管理／取消連結不自動放到共用網站。
- 旅中以主揪回報或當次要求觸發調整；備案可離線，動態資訊查到才算更新。不宣稱背景監看、定位或未實際建立的提醒。
- 回覆配合使用情境：初輪只呈現必要缺口與可行下一步，完整欄位留正式紀錄。旅中急迫調整先用約150字內給最多三個立即動作與關鍵不確定，再附可展開的路線、理由或通知；不要讓主揪從長文找救急步驟。

## 預設交付與完成判定

按當次範圍交付，不為小修改重建全部。完整旅行預設包含：

1. 主揪版正式行程與待辦：旅伴需求、每日可執行路線、固定預約、成本、備案、負責人與期限。
2. 同行手機入口：穩定網址與單一分享QR，直接使用線上日期／行程、導航、集合與預約；景點女聲在對應日期的景點卡出現，問路／點餐保留已確認的外語聲音。首頁不要求下載、顯示製作版本或試聽公告；約定範圍內免登入使用。
3. 主揪離線與非手機備援：另設備份入口、必要文字／PDF與紙本；同行者不必下載整份HTML。每人仍保存自己的正式票券與最小求助資訊。弱網、無網或特殊需求時，依當次條件另選離線模式並驗證。
4. 約五分鐘的教學與操作練習；不方便用手機者有紙本或協助者。
5. 預算／代墊／退款／結算紀錄；只有被授權的受眾可看適當摘要。
6. 已測／未測／受阻的驗收紀錄，標示版本、裝置及仍需使用者處理的一個具體下一步。

規劃完成、行前就緒、旅中可接續、旅後結清分開記錄。未開放預約、待付款或待實體手機驗證，記負責人／期限／下一步；核心缺陷修正後才標通過，不能用產生檔案代替驗收。工具不足時可交付有用的階段成果，但不能把全部目標標完成。

結束回覆提供可開啟成果、關鍵取捨、尚待處理事項與最短使用方式。重要更新在主揪交付說明交代影響及誰需更新備份；不把技術更新公告堆在同行首頁。發布成功不等於同行者已讀。

# 驗收與情境

## 用任務驗收

每次記版本、資料來源、環境、實際結果與證據。只驗證當次變更和合理受影響功能；新建完整交付則覆蓋下列核心任務。失敗修正後重測，不用文字宣稱或靜態程式存在取代操作證據。

| 任務 | 可觀察結果 |
| --- | --- |
| 新同行者開入口 | 原備忘錄精簡為入口卡；掃原QR／點連結直接用線上行程，無下載、版本或試聽公告擋住首頁。符合約定登入方式，無主揪帳號也能取得授權內容；相機實掃另記 |
| 主揪備份 | 另設備份入口，頁面／檔名版本一致，實際下載比對產物與重開；舊HTML不自動更新，只有持有備份者需重存。一般同行不需下載整份HTML，個人正式票券仍各自保存 |
| 找今天與集合 | 日期可切，當地時間與更新版次清楚，集合點和協助方式可找到 |
| 走下一段 | 點擊後是正確分店／入口／模式；關閉或返回仍在原日原站原位置 |
| 報到 | 依日期找到人數、拆單、代表人、付款餘額；單號可複製，大字與必要正式原件可用 |
| 語言與導覽 | 主揪製作階段先短試聽確認再整批；旅客首頁無試聽公告。女聲在對應日期景點卡，問路沿用已確認外語聲音；線上按需播放有實際進度，暫停重聽／切頁／互斥正常 |
| 弱網／斷網 | 必要資料完成保存，斷網離開再重開仍可讀；需網路功能明確標示 |
| 成員負荷 | 實際步行、階梯、行李、休息和時間接得上；備案適用最需要協助的成員 |
| 帳務 | 已付／承諾／估算不重算，退款連原筆，每筆分攤等於實付淨額，各人結算淨額總和為零 |
| 更新回歸 | 原QR／網址、原預約、導航、音訊、地圖和備援未被無意刪除；舊檔差異與重下載提示清楚 |
| 受眾 | 實際部署內容與下載資產未含未授權個資、管理連結；不能只看畫面隱藏與否 |
| 完成狀態 | 區分能做、計畫、文字草案、實際產物與正式提交；只列「可交付行程／文稿」不能把尚未寫出的行程／文稿標成已完成。缺目的地、日期或原件時列依賴與待補，不編造成果 |

同行入口更新依 完整流程與逐人清單（見「來源：references/companion-flow.md」章節） 分別驗證同行線上入口到預約，以及主揪備份與離線。檢查下載檔中的相對資產、更新入口與音訊；缺少相鄰檔案時不能假設單檔能用。公開分享skill時，只發布通用指引與合成範例；不連帶發布真實旅遊資料、附件、原信、QR或驗收截圖。

## 證據層級與交接

分開標示：文件核對、靜態驗證、手機尺寸瀏覽器、桌面實際播放、實體手機、App切換、實體掃碼與飛航模式。影像QR解碼不等於相機實掃；桌面播放不等於手機聽到；看得到附件不等於已下載。

本人裝置才能驗證時提供一個短測試動作並記待驗收，照常完成其餘工作。無工具、無登入或服務限制記受阻原因，交付可用替代及一個具體下一步；不把受阻標通過。

若工具禁止本機HTML直開或無法切真離線，不繞過限制。分開記「下載內容一致」「同內容網頁互動通過」與「離線檔直開未測」；不以相同位元或程式碼存在推定檔案預覽器可播放。更換下載方式取得正式檔案可核對內容，但不會補足裝置端執行證據。

規劃完成：願望取捨、時間、交通與預算可行。行前就緒：必要預約、個人票券、同行上網與線上操作、主揪備份、教學與核心驗收完成。旅中可接續：最新狀態、變更、待辦與備案明確。旅後結清：退款與代墊確認，未結項保留。四者不可混為一個「完成」。

## Skill本身的情境驗證

變更本skill時，可用獨立情境評估；不需操作真實訂單、付款或發布個資。給執行者當前skill及最低必要假資料，不提供預期答案。保存實際輸出後，再依上表核對，區分演練與產品實測。

適合的情境：未定地點且成員需求衝突；有固定預約但交通不可行；拆單與付款證據矛盾；無發布工具但要QR；旅中延誤又有人不能走；不同參與者與退款的分帳；新增音訊後原地圖或離線版本失效。

自然語音更新另檢查：尚未試聽不可先整批；同一樣本已確認且條件未變不重問；服務失敗不可默默降級成基礎系統聲音；改中文聲音須保留原外語、預約、票券與分享入口；正式離線下載內容須與新音檔一致。這些流程檢查不代替使用者對自然度的主觀聽感確認。

評估核心：是否查核／承認未知、保留已定事項、給可執行行動、遵守授權受眾、正確計算、如實報告能力和測試。失敗導致窄幅修訂，修訂後重跑受影響情境。

# 預約、受眾與帳務

## 預約帳本與證據

每筆保存預約ID、供應商與分店、當地日期時間／時區、人數／拆單、代表人、票種、原幣總額、已付／待付、報到期限、取消更改規則、確認原件與實際入場／乘車憑證位置。訂單ID、付款收據號、登記序號、正式票券分欄，不互相代稱。

預約狀態（建議→查到空位→準備好→已提交→正式確認／失敗／待查）與付款狀態（未付／待驗證／已付／退款中／已退）分開；已付款仍可能待出票，查到空位仍可能未保留。各有來源與時間。

拆單如2＋2＋1保留三筆單號、代表人與金額。正式憑證可能每人每程不同，分享QR與普通單號不能入閘。不確定憑證要求時查供應商，不用自己製作仿票。

先找現有原件與授權的確認信來源，核對改期、取消、付款與最新版本；同主旨可能合併，多封信不能只取第一封。必要時在授權範圍查封存／垃圾桶，不能過早宣告缺件。原件不改寫，另做易讀摘要；未找到就標缺口，不推算號碼或付款成功。

## 執行與授權

主動完成研究、比價與可審閱的準備。具體提交／付款前確認當次授權是否涵蓋供應商、日期、人數、項目、金額上限與重要取消條件；遵守工具當次規則。已有授權且條件不變就繼續，費用／時間／票種／取消條件有實質差異才再請決策。

以官網原文核姓名與欄位，自動翻譯顯示不作原始資料證據。需本人處理登入、卡片或銀行驗證時提供確切接續點，不要求在聊天提供卡號、CVC或驗證碼。成功要看供應商正式結果與原件；超時、頁面不明或扣款疑慮先查訂單與確認信，不重複付款。相同錯誤重現先診斷，無法確認就保留待查與安全下一步。

成功後同步預約卡、行程、費用與相關備援；未提交或未聯絡一定明載。未開放預約、待付款、待票券、待改期各有負責人、截止時間與下一步。需要未來提醒就使用可用排程工具建立並驗證；不能建立時給可匯入清單並標未設，不聲稱會背景記得。

## 分享範圍

先確認主揪、協助者、同行與團外受眾；依任務分配必要資訊，不固定要求兩個網站或強制加密。免登入持有連結者可能轉傳，讓使用者理解後選擇分享方案。

原件可保留私有位置，共用頁只放授權的必要內容。含卡片、私人聯絡、護照、健康、管理／取消連結的文件，先抽取適當摘要或遮蔽，不能因同行可以看單號就自動公開完整原信。不要把敏感資料藏在前端HTML、JavaScript、下載檔、音檔或隱藏欄位後宣稱保密；真正受限內容須有適當存取控制或不部署。

## 預算與結算

先確認包含項目、整團／每人額度、共同與個人支出、備用金及付款方式。分開顯示已付、已承諾未付、估算；同一預約的付款不能在總額重算一次。原幣為準，換算附匯率、日期、來源與費用假設，不把估價或換算當帳單。

每筆費用記付款人、參與者、分攤規則（平均、份額、指定額、個人）、原幣與實付、手續費處理、憑據、是否結清。不同房型、分組車、不飲酒或未參加活動不預設均攤。

退款連回原費用，區分應退、退款中與實際入帳；保留修改紀錄，不把原件刪掉掩蓋。依約定幣別結算，不跨幣直接相加。尾差分配明載；每筆分攤合計須等於實付淨額，每人淨額總和為零。輸出誰應付誰的建議與未決項，轉帳本人處理，收到回報才標結清。

# 同行完整操作流程：線上使用與主揪備份

適用於同行指南更新及出發前複查。預設同行直接用線上版，主揪下載備份；沿用可靠入口、原預約、PDF和QR。不要求每團都建網站、備忘錄或音訊，缺工具時給可用替代。當次明確要求全員離線或目的地弱網時，才把下列備份流程套給相應旅伴。

## 從旅客第一步開始

預設實際順序：精簡備忘錄／共用說明 → 點文字入口或掃原QR → 選日期 → 看行程、集合與交通 → 在對應景點聽女聲／溝通卡播外語 → 查預約與正式票券 → 外開導航／切App再返回。全程不先下載整份HTML，不先閱讀版本或試聽公告。

外層入口卡只留名稱、日期、單一網址／QR及必要提醒；原預約與附件放可收合備查。先保存本文與附件基準再局部調整；不覆寫整則而丟PDF、QR或收據。更新說明放主揪紀錄，同行首頁不堆女聲換版、檔名大小或製作中資訊。同手機不能掃自己的QR時提供直接可點連結；圖檔解碼與相機實掃分記。

首頁只給日期與當下任務，景點導覽留對應日期的景點卡，不放集中故事／試聽入口。使用者按景點播放即可，不假定定位抵達；線上音檔按需載入，不背景抓整個離線包。中文女聲與問路外語各自驗證，不能因刪男聲試聽公告就刪掉真正的問路男聲。

## 主揪下載入口與版本辨識

此節適用主揪／協助者或當次指定的離線使用者，不是一般同行首頁步驟。

- 另有易取用的備份入口；版本、更新日期、檔名、大小與下載教學放此頁或交付說明，首頁不宣傳。獨立URL不是私人權限，敏感原件沿用適當受眾。
- 備份頁與檔名有一致、可辨認版本／日期，例如虛構的 `主揪備份_2027-04-08_v3.html`；下載等待、去哪找檔案、如何重開有短說明，避免誤開舊檔。
- 由正式備份入口實際下載，核對檔名、內容與版本；用雜湊／位元比對確認本次產物。工具若忽略下載檔名或被阻擋，分記限制，不把本機原檔當正式下載驗證。
- 網站更新不會改已保存HTML；只通知持有備份者重存。未變PDF與票券可沿用，有版本落差則說最新依據，不要求全團重下。

## HTML預覽、單檔與備援

手機「檔案」或聊天App預覽可能不支援JavaScript、音訊、剪貼簿與返回；下載完成／能看文字不等於離線就緒。記實際App、播放進度與使用者聽感。不能互動時用線上入口、已同步文字、已存PDF、正式票券與紙本；不保證手機瀏覽器能直接開本機HTML。

主揪單檔要包含必要音訊、圖片、摘要、文字與控制；若仍用相鄰檔案，需完整打包或改內嵌，不能把線上音檔路徑當離線成功。單檔「取得更新」回穩定備份入口，不指向不存在的相對bin／HTML。外開導航、官網與即時交通仍需網路。

不繞過工具對file協定、離線或手機操作的限制；完成可做的內容比對和線上測試，分別記錄，不能冒稱真離線通過。

## 預約與播放的現場可用性

用日期、店名、代表人及單號搜尋，測複製、放大與關閉。無獨立預約號時從原件核對姓名、時刻、人數，放摘要及工作人員卡；收據仍叫收據號，拆單全部顯示。正式憑證沿用授權位置，不把主揪登入變成唯一取得方法。

在相應景點卡手動播放，觀察實際時間進展，測暫停、續播、重聽、切頁停止、外語互斥。音色由使用者確認；解碼／桌面播放不代表手機親耳通過。導航返回保持原日期、位置與展開狀態。

## 逐人親手實測範本

使用當次資料替換填空；版本與紀錄留主揪處，不要求同行在產品首頁辨認工程版號。

```text
同行線上操作｜日期：〔旅行日期〕｜成員：〔代號〕
□ 入口：掃另一裝置／紙本的原QR或點連結，符合約定登入方式；不必下載整份HTML，首頁能直接選日期。
□ 行程：找到今天、集合與求助；開下一段導航、切App再返回，仍在原日期位置。
□ 預約：找當日代表人、所有拆單與必要原件；試搜尋、複製、放大及關閉。
□ 聲音（有提供時）：在對應景點／外語卡親耳試播；暫停、續播、重聽、切頁停止、不重疊，確認耳機／藍牙。
□ 上網與備援：確認旅途網路可用、主揪／協助者或紙本能提供必要備援；線上成功不標全團離線就緒。

不能完成時回報手機型號／開啟App／卡住步驟；未確認保持待測，指定協助或紙本替代。
```

```text
主揪備份實測｜版本／檔名：〔當次資料〕｜裝置／App：〔實際填寫〕
□ 從正式備份入口下載完成，辨認版本，關掉再重開；核對內容，舊HTML不自動更新。
□ 主揪保存必要指南、預約原件與PDF，另一位協助者或紙本持有關鍵集合／求助資料。
□ 飛航模式＋關Wi-Fi，離開App後重開已存指南、文字／PDF，測實際需要的音訊與靜態地圖。
□ 預覽不能互動時有可用替代；官網與新算導航仍需網路，未測項不標通過。
```

只把適用項目列待測；不強迫一般同行通過整包HTML離線測試。主揪一台正常不代表其他人的線上操作和票券已確認；協助者或紙本可達成同一現場任務，但要記方法。

# 景點自然女聲：先試聽，再整批

中文景點導覽優先用溫暖自然、像真人導遊的台灣華語女聲。此偏好來自使用者實際試聽後的明確選擇；若當次另指定音色、語言或語速，依當次選擇。不要把「有聲音」「沒有報錯」或音色名稱含Neural，當成自然度已獲認可。

## 已成功且獲確認的配方

| 項目 | 本案驗證參數 |
| --- | --- |
| 服務／音色 | Microsoft線上語音，`zh-TW-HsiaoChenNeural` |
| 語言 | 台灣華語，`zh-TW` |
| 語速 | `-5%` |
| 音高／音量 | `+0Hz`／`+0%`，不另外變調或套機器效果 |
| 文稿 | 有現場看點、自然短句與段落停頓；不加背景音樂掩蓋機械感 |
| 試聽 | 約20–30秒，本案24.6秒，由使用者實際聽後確認 |
| 完整導覽 | 依內容決定長度；本案12段各約55–61秒，並非所有旅行的固定秒數或段數 |
| 本案產物 | MP3、24kHz單聲道；線上按需播放音檔，主揪單檔備份內嵌，手機不需即時合成 |

本案使用既有 `edge-tts 7.3.1` 成功製作，未啟用付費API。這是可重用配方與歷史驗證，不能保證服務未來永遠可用、免費或參數不變。執行前檢查當前可用工具與服務；不因本文件自行安裝、更新套件或啟用付費方案。

## 製作確認與旅客播放分開

短試聽交給主揪在製作階段確認，不是同行掃QR後的前置步驟。正式導覽按鈕放對應日期的景點卡，手動點播；首頁不放「先試聽」「聽一段故事」、音色換版或下載公告。線上按需載入音檔，主揪備份另內嵌／打包；問路或點餐沿用已確認的外語聲音，包括原男聲，不因取消首頁試聽而移除。

## 製作順序

1. 確認當次合成服務、文稿外送及整批製作範圍是否已有授權；已有明確授權且條件不變就繼續。音色偏好可沿用，但不能把這趟合成授權視為其他任務的常設外送或付費授權。只傳不含個資的景點文稿，不送訂單、旅伴聯絡或私人資料。
2. 挑一小段真實導覽文稿，涵蓋地名等容易念錯的部分，製作約20–30秒試聽。用正常標點與段落安排呼吸；不要把每幾十字切碎重接，破壞語氣。先對齊聲音與文稿節奏，無須重做所有內容。
3. 以可直接播放的本機音檔或可用播放器交付，請使用者確認音色、自然度、語速與關鍵發音。**未確認就停在試聽，不先製作或發布整批。**同一批已有明確確認、聲音與設定未變，不重複索取相同確認。
4. 確認後以同一音色、語速、音高與相同處理方式產出整批；不要試聽用神經女聲，正式版換成基礎系統聲音。變更音色、引擎或明顯節奏時先做新短樣；個別錯字修正而配方不變，只重做受影響段。
5. 每段優先整段合成以保留連貫語氣。必要時按自然段切分，勿任意在句中拼接；特殊字的讀音替換另存合成文稿，保留展示文字與來源。例如本案合成時將「〇」改「零」、「亀」改「龜」，並未改動歷史內容。
6. 完整解碼檢查各檔，保存音色、參數、合成文稿、時長、大小與雜湊；這些只證明檔案與配方，不能冒稱人工聽過全部。另驗證實際播放進度、重聽、切頁停止及與其他音訊互斥。
7. 用新資產檔名或適當版本策略更新手機與離線音訊，確認內嵌資料與正式檔案相同。原文字來源、日文等外語聲音、預約、PDF、地圖、網址及QR須比對保留。更新播放器的聲音標示，避免畫面仍寫男聲。
8. 正式發布後由原網址進對應景點核對音色與串流播放；另核主揪實際下載備份與本機新版的雜湊。只提醒持有離線備份者重存，不要求一般同行下載；實體手機／飛航模式另列驗收，不能以桌面或快取成功代稱通過。

## 可重用的呼叫形狀

當次授權與服務能力確認後，可用已可用的Python工具；不要求其他助理依賴本機暫存路徑：

```python
import asyncio
import edge_tts

async def synthesize(text, output_path):
    voice = edge_tts.Communicate(
        text, "zh-TW-HsiaoChenNeural",
        rate="-5%", pitch="+0Hz", volume="+0%",
        connect_timeout=15, receive_timeout=35,
    )
    await asyncio.wait_for(voice.save(output_path), timeout=60)
```

僅在使用者已選此服務且可用時使用此形狀；不同工具先核實對應參數，不盲目套用。未取得使用者試聽確認前，只呼叫短樣本。不要把不受支援的自訂SSML或表演風格標記塞進文稿讓它被念出來。

## 失敗與機械聲處理

若無音訊、服務受限或音質不合格，先保留文字稿與現有可用版本，記錄錯誤並做有限診斷；同樣失敗不連續轟送，不自動換供應商或改付費API。需要不同服務時，說明具體替代後依當次授權處理。

**不要默默用Apple Eloquence Reed、基礎Meijia或瀏覽器預設speechSynthesis，冒充已確認的自然女聲。**本案原Reed基礎男聲能正常播放，仍被評為機械；換性別或略調速度不等於問題已解決。本機若有合適的高品質聲音，也須先短試聽，明示與既有配方不同，確認後才用於整批。

# 匿名旅行案例：可重用的經驗

來源是一趟家人朋友日本秋季旅行的歷史討論與製作驗收。已移除姓名、信箱、單號、網站、筆記ID與私人附件；以下是方法教訓，沒有重新查證任何景點今日狀態。

| 發生過的問題 | 下次如何處理 |
| --- | --- |
| 手機頁面精簡後漏掉預約與外語卡 | 先記現有功能基準，減字後做回歸；不要用「更簡單」默默改變功能 |
| 發音按鈕存在，手機語音清單卻空白 | 實際播放與使用者聽音驗證；準備音訊或文字備援 |
| 基礎系統男聲可播放，卻被使用者評為機械、不好聽 | 可用不等於好聽。優先自然台灣女聲，先用約20–30秒真實文稿確認音色與語速，再製作全部；失敗時不能偷偷退回基礎音色 |
| QR難找，多入口與舊檔讓主揪困惑 | 一個穩定同行入口，清楚受眾與版本，舊教學歸檔 |
| 確認信需主揪登入、同主旨信被合併 | 每筆預約獨立摘要與原件入口，保存供同行使用的必要憑證 |
| 接駁發車被含糊寫成到站；纜車與花園不同開放時間 | 分別核對，倒推真實可參觀時間，提早出門不能讓景點提早開門 |
| 地圖理論步行分鐘數太樂觀 | 加入團體步速、進站、電梯、行李與休息；不固定所有人都適用 |
| 訂不到熱門交通後沿用網友路線 | 核休館、車輛限制、入口、體力和固定晚餐，挑必要景點與刪除點 |
| 新增景點讓行程越排越滿 | 先討論取代休息或候補的成本，保留重要預約與成員負荷 |
| 證據只有收據號，沒有另列預約號 | 保持原來類型，不能把參考號冒稱有效入場憑證 |
| 自動翻譯把正確英文姓名顯示成錯中文 | 切回原文核對，避免因翻譯錯誤改掉正確資料 |
| 受眾決策後來變更，舊資料仍寫私人版 | 依最新明確決策處理，不把曾經的私密／公開選擇當永久設定 |
| 新網站更新了，舊行程PDF仍保留 | 明示版本落差與最新指示，必要備援同步；保留原件不等於默認內容仍最新 |
| 桌面390px測試被誤認為iPhone驗收 | 逐項記證據層級，不能代稱原生App、實體出聲或飛航模式通過 |
| 曾為解決下載難找，把下載與試播搬到首頁，結果仍像製作中 | 最新預設改同行直接線上使用；主揪備份另有入口，下載教學與版本僅放備份頁／維護紀錄，首頁只放旅行任務 |
| 不同版本的主揪備份檔名相同，容易誤開舊檔 | 備份頁與檔名有可辨認版本／日期，只通知持有者重存；普通同行不需在首頁辨認版本 |
| 下載成功，手機檔案預覽卻不能點按或出聲 | 預覽不是完整瀏覽器；先辨認開啟App與支援情況，給連網入口、原生文字及已存PDF備援 |
| 單檔HTML仍引用不存在的相鄰下載檔 | 分別檢查網站與已存單檔；內嵌必要資產，從單檔取得更新時回穩定線上入口，不指向不存在的本機相對檔案 |
| 無預約號的報到卡只寫「核對姓名」，現場仍要翻原件找姓名 | 由原件核對後把代表人、日期、時刻與人數寫入摘要及放大卡；保留正式憑證入口，不發明預約號 |
| 主揪一支手機正常，便把全團標為就緒 | 按角色實測：同行測線上入口、聲音、預約與個人票券；主揪另測下載重開／真離線。不能操作者有協助者或紙本 |
| 景點故事與音色說明集中首頁，還沒出發就被要求試聽 | 製作短樣給主揪確認；正式故事只放相應日期景點，問路男聲放溝通卡，手動點播 |
| 多輪更新公告讓備忘錄越來越長 | 備忘錄只保留日期、穩定連結與QR；原預約PDF收合備查，更新紀錄留維護處 |

此案例沒有完整保存最早選地理由與每人願望，不能假裝已復原。新旅行仍需短訪談；日本、長輩、五人、某款備忘錄或分兩台車均非通用強制條件。景點聲音已依使用者後續明確指示，優先採用自然台灣女聲；配方及試聽確認流程見 自然女聲（見「來源：references/guide-voice.md」章節），不是把本案例舊男聲延續為預設。

# 同行線上入口、主揪備份與現場操作

## 入口與產品首頁

預設同行掃單一穩定HTTPS網址／QR，直接使用線上行程，不要求先下載HTML或音檔。先確認受眾、旅途中上網條件及可用工具；明確要求全員離線、弱網或特殊需求時才調整，不能為簡化介面宣稱不需要網路。分享QR與正式票券QR清楚命名，沿用已發出的可靠入口。

首頁任務優先：日期／今天行程、交通、集合、當天預約與求助，可手動切日期。顯示當地時間；版本、製作狀態、更新日誌、檔案大小、下載教學與試聽確認留在主揪交付／維護紀錄或備份頁，不放同行首頁。必要的實際集合或路線變更仍須在受影響日期清楚標示。

備忘錄／共用說明是一張入口卡：旅行名稱、日期、單一連結／QR及一句必要提醒。網站已有的操作說明不再堆到外層。原預約、PDF、收據與附件保留，放備查區／可收合段落；縮短前先記本文和附件基準，不整則覆寫。

手機能單手操作、大字清楚、無水平捲動，資訊逐層展開但不刪功能。每日預約直達，單號可複製、放大給工作人員看；必要原件少步驟開啟，不能只有主揪登入的Gmail連結。

## 導航與聲音放在使用情境

地圖分段、模式與目的地明確，總圖有停留與集合點，可放大返回。外開導航、票券或重載後保留原日期、位置與展開狀態；固定操作不遮內容。

景點故事入口只在對應日期的景點卡出現，點選才播放，不在首頁集中宣傳「聽一段故事」或先放試聽。沒有定位授權時，不宣稱能偵測已抵達；由旅客選日期、景點及按播放。文字稿含現場看點、可靠典故與出處，不編故事。

中文景點導覽優先溫暖自然台灣女聲；先短試聽再整批（見「來源：references/guide-voice.md」章節）是主揪在製作階段確認音色的流程，不是全體旅客的首頁步驟。更換女聲不連帶改動已確認的問路／點餐外語聲音；原本男聲可在相應溝通卡繼續使用，不另要求下載。外語先有中文意思、核對後手動朗讀，不開卡即出聲。能暫停、續播、重聽，切頁停止、播放器互斥，寺院提醒戴耳機。

線上音訊優先按需讀取實際音檔，不為啟用聲音把整個音訊庫或離線包塞進首頁、背景預先下載。主揪的單檔備份則內嵌或完整打包必要資產。瀏覽器語音清單可能為空，須驗證真正播放與聽感；無工具時提供文字並如實標未完成。

## 主揪備份與失聯備援

主揪另有穩定、容易取用的備份入口；下載區有可辨認的版本、檔名、大小與手機開啟說明，完成下載後驗證。這些資訊不進同行首頁，也不把下載設成同行看行程的前置條件。隱藏入口不等於權限隔離，敏感備份要依已約定權限保存，不能因另建網址便稱私人。

主揪保存必要行程、預約摘要、原生文字／PDF與正式原件；至少有另一位協助者或適當紙本持有關鍵集合／求助資料，避免只靠一支手機。每位旅客仍保存自己的正式票券及最小緊急資訊；「主揪才下載整份行程」不免除個人票券責任。

線上版需網路，快取不等於已離線就緒。PDF需真的下載、備忘錄需同步；HTML檔案預覽不一定支援互動／音訊。主揪備份以實體手機飛航模式＋關Wi-Fi、離開後重開驗證；不能操作時記待本人測試。離線導航新算路、官網與即時交通另標需網路。細節見 角色分工與實測（見「來源：references/companion-flow.md」章節）。

## 約五分鐘教學與逐人驗收

同行每人親手練：掃QR／點連結並存入口 → 選日期和集合 → 開導航再返回 → 查當日預約／出示正式票券 → 到相應景點卡或外語卡試播、停止。核對日本等目的地上網方式、耳機與協助者，不強迫下載整份HTML或播放全部故事。

主揪／協助者另練備份下載、辨認版本、關網重開及紙本替代。不能用手機者有指定協助者。依 逐人實測範本（見「來源：references/companion-flow.md」章節） 分角色記錄；主揪離線通過不代表同行線上操作和正式票券都通過。

## 發布與變更

正式資料為單一來源；變更先保存基準，再同步受影響路線、地圖、預約、音訊及主揪備份。保留原件時標明舊PDF等版本落差與最新依據。由原網址／QR確認發布與快取；存下的HTML不會自動更新，只提醒持有備份者重存，不每次要求全團下載。

更新細節與未測項目交付主揪，通知是否發送／旅伴是否確認分開記。一般同行畫面只放能幫他決策與操作的內容；臨時集合或重要路線變更按授權通知，不能因首頁簡潔而隱藏現場必要資訊。無發布工具時交付本機資料及分享方法，明示沒有可掃的線上入口，不把localhost當外地旅客網址。

# 規劃與帶隊

## 分階段收資料

先讀可取得且已授權的現有資料，不把找得到的事實丟回使用者。每輪只問當下影響決策的缺口；既有事實附來源，主觀願望與最後決策由當事人確認。

- 旅行骨架：目的、出發地、日期與彈性、同行人數、總／每人預算及包含項目、已訂交通住宿、主揪與協助帶隊者。
- 逐人需求：必做願望、不能接受的事、可連走時間、坡階限制、休息、早起／夜歸接受度、飲食過敏與禁忌、語言、手機能力、是否接受分組。只問影響旅行的必要協助，不要求提供完整病史。
- 現場條件：行李件數／尺寸、房型與分房、同行關係與需要共同活動的時段、通訊、付款能力、可用裝置。年齡不等於步行能力；無回覆不能視為同意。

旅伴短問卷可只問「最期待一件事／最不想一件事／體力休息需求／飲食限制／手機及分組協助」，主揪彙整後確認衝突。主揪發布正式行程，協助者拿得到自己分組必要資料；不要求每團都建表單、投票系統或登入帳號。

## 選地、日期、景點與餐飲

未定時提出約2–3個可行組合，比總成本、門到門交通負擔、季節天候、人潮、成員適合度、可訂性及取捨，附推薦理由。不要在日期未定前安排大量不可退預約。

景點與餐飲以願望和路線共同篩選。確認正確分店、營業日、餐期、容納人數、菜單價格／服務費、過敏處理及是否接受預約。訂不到的主願望提供替代，不擅自視為已滿足。候補不得同時占用必做時段；新增必須寫清取代與增加的步行／費用。

查核來源包含旅行當日適用性；區分往年經驗、今年公告、預測與當日現況。社群攻略是線索，不能取代休館、交通管制、售票條件等官方資訊。過期規定或年份不同的花況不得直接引用為今年結論。

## 每日可執行路線

先放固定預約與航班／列車，再安排交通、報到、取行李及必要休息，最後放可刪景點。每段記：起訖點、出發／抵達、模式、方向／站系／出口、實際步行、停留、費用依據與備案。

時間包含團體步速、找路／月台、電梯、候車、排隊、上下車、廁所與休息。區分最低理論時間、團體規劃時間、尚不確定等候，避免精確假象；不固定套用每團相同緩衝。

- 車輛以乘客數（不含司機）和行李容量確認，不能只看車型座位。兩車先有分組、協助帶隊、相同目的地卡與集合方式；能否同時叫到仍需確認。
- 地圖核正確分店、站系、航廈、站牌方向、可進入入口與上下車位置。導航按實際一段一段拆，不用模糊總路線或當下Maps預設模式替代。
- 行李是獨立工作流：誰寄存、哪個櫃台、件數、領取單、領回期限、如何送下一站；貴重物、用藥及正式票券隨身。
- 不用全天包車解決本來受步行區／管制限制的路段。比較包車、單段車、大眾運輸的總成本、等待與搬運負擔；交通加價列全團與每人差額供主揪取捨。

## 備案與行前準備

備案寫成「觸發條件／最晚切換時間 → 誰決定 → 下一個動作 → 集合與費用影響」。照顧下雨、疲累、排隊、無車、錯過交通、臨休、走散與手機失效；不能把不適合拖箱步行者放入步行備案。保住重要預約，若仍不可行，明列重排或改約選擇。

行前清單依目的地與成員生成：證件／入境、保險聯絡、通訊、付款、行李限制、衣著、必要用藥、協助服務、票券。每項有負責人、期限、確認依據與狀態。醫療、入境或保險專業問題用當前官方／合適專業來源，不憑技能中的通用文字作個別判定。

緊急卡包含經當地官方核實的緊急號碼、住宿地址、主揪聯絡與固定集合辦法；提供離線版本。急迫危險先提供可立即採取的求助步驟，再處理行程。位置與健康資訊只交付需要的人。

旅中先取得現在時間（當地）、位置、剩餘固定預約、成員狀況，再調整受影響路段；可安全採取的行動先給，查不到的營運與車位保留不確定。優先呈現最多三個立即動作與最重要的不確定，分析與正式紀錄留後，避免現場長文。重算後續、分組集合、費用與通知，不只改單一景點。

# 正式旅行資料契約

這是建立或整理資料時的最小欄位指引，不強制把既有專案改成某種格式。用JSON、試算表或結構化文件皆可；避免多份互相衝突的正式來源。確認原件獨立保留，產生物記所依據版本。

| 區塊 | 關鍵欄位 |
| --- | --- |
| 旅行 | 穩定ID、目的、起訖、出發地／目的地、各地時區、版本、當地及UTC更新時間、主揪、階段 |
| 成員 | 代號、角色、必要需求、願望優先度、步行休息、語言／手機、分組意願、分享範圍、待確認欄位 |
| 決策 | 決策ID、選項／取捨、確認者、時間、來源、取代的舊決策 |
| 每日／路段 | 穩定ID、起訖／入口、當地起訖時間及時區、交通模式／方向／出口、步行量、休息、停留、集合、固定預約ID、地圖與查核依據、可刪性 |
| 預約 | 獨立ID、供應商／分店、人數與拆單、代表人、時間／時區、票種、訂單／收據／票券各自欄位、預約狀態、付款狀態、報到要求、取消條件、原件、來源時間 |
| 授權 | 當次操作、對象／受眾、日期項目人數、金額上限／幣別、條件、證據、已用與未用範圍；不存憑證秘密 |
| 費用 | 獨立ID、預約ID、原幣、已付／承諾未付／估算、付款人、參與者、分攤規則、實付／退款與狀態、換算依據、手續費與尾差、結清狀態 |
| 備案 | 觸發條件、最晚切換時間、決定者、可執行動作、集合與費用影響、適用成員、需網路能力 |
| 待辦 | ID、負責人、到期時間／時區、依賴、狀態、下一步、提醒是否實際建立及回執 |
| 發布物 | 受眾、同行線上／主揪備份角色、上網條件、穩定網址、QR目標、版本與更新時間（維護紀錄）、備份入口及下載檔名／大小／雜湊、離線內容、原件位置、誰須重存、通知狀態；版本欄位不要求露在同行首頁 |
| 驗收 | 任務、版本、成員代號、裝置／實際開啟App／瀏覽器／網路、步驟、預期、實際結果、證據層級、通過／失敗／未測／受阻、協助者／下一步；逐人結果保留於團體授權範圍，不公開健康或聯絡資料 |

未知用明確的「未提供／待查／未確認」或null，不能用0、false或空白冒充已確認。來源有原始網址／文件位置、適用日期與查核時間，注意勿在共用輸出洩漏私有路徑與敏感查詢參數。

狀態寫入採小範圍更新，保留原件與修改紀錄。避免序號重排導致別人的已存連結失效。成本加總依費用ID去重；同一筆預約付款與其帳本費用不得重算。

跨時區移動用明確日期與當地時區，避免只寫「明天下午」；跨日與夏令時間不能只用固定小時差推算。行程頁以當地資訊服務旅客，工程紀錄可另存UTC。
