# 跨平台實際匯入與情境驗收

日期：2026-11-16。使用者明確授權後，在自己的Gemini與Claude帳號介面匯入並測試；僅使用公開skill與虛構題目，不傳送實際旅行資料。原答、對話與截圖留於私有工作紀錄，此頁只公布匿名結果。

## 安裝結果

| 平台 | 實際確認 |
| --- | --- |
| Gemini網頁Skills | 匯入ZIP，主指引與八份參考文件完整；修正後替換套件，重新安裝；從 `@` 選單選取後實際讀取 `SKILL.md` 與 `references/acceptance.md` |
| Claude網頁Skills | 匯入ZIP並確認開關啟用；主指引、八份參考與授權文件可見；修正後儲存帳號端v2並在新對話讀取新版指引 |

核心修正收錄於公開v1.2.0；Claude帳號中的v2是其自己的版本編號，不等於GitHub發行版號。

## 三個情境的結果

| 情境 | Gemini | Claude |
| --- | --- | --- |
| 六位旅伴只有主揪手機測過離線，能否宣布全團就緒 | 初測通過：其餘逐人待測、六項清單與協助備援 | 初測通過：逐人實測，不能單機代替全團 |

共同缺陷：兩平台在第二題只列「可交付項目」，卻把尚未產生的行程／文稿標成已完成。修正主指引與驗收文件後，兩者均能明示未產出實際行程、訂單、網站或音檔；缺資料與缺工具的工作保持待補／未完成。

Gemini有一次覆驗說沒有載入任何skill，該次不算技能測試通過。診斷後，從 `@` 選單實際選取技能並將假設情境與真實工具狀態分清，再覆驗受影響題目，確認讀到指引且回答符合要求。這不保證任意措辭都能自動觸發；不確定是否載入時，請明確選取並查實際讀檔情況。

實際外送：Gemini三次、Claude兩次。第一輪每個請求包含三個獨立虛構情境；後續只覆驗缺陷及載入問題，未把已通過情境反覆重送。當次介面顯示Gemini Hydrogen高與Claude Opus 5.5中；產品、帳號與模型後續變動需重新確認。未啟用額外付費方案。

## GitHub連結安裝的實測界線

Claude在覆驗中實際讀到 `INSTALL.md` 與 `install.json`，並確認自己的普通聊天工具能讀取／下載，卻不能寫入帳號端Skills設定；同名skill已存在，沒有重建或覆寫。

因此，[AI安裝入口](../INSTALL.md) 的承諾是：有檔案或技能管理工具的AI可依環境安裝；沒有該能力時給對應ZIP與一次人手上傳步驟。不能保證只貼GitHub網址，就能跨過平台權限完成永久安裝。讀過指引、在本次對話使用、帳號永久安裝與測試通過是不同結果。

原生App本次未另跑模型測試；此結果不自動代表所有CLI、手機介面、企業政策或未來模型均通過。這是指引的情境行為驗收，沒有真的訂票、付款、部署旅遊網站、合成聲音或替旅伴完成手機飛航模式測試。
